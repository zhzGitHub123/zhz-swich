# 技术决策记录

## 已确定

### 使用原生 Swift

理由：满足性能、耗电、内存和系统集成目标。避免浏览器壳和跨平台运行时带来的常驻成本。

### SwiftUI 作为主要 UI

理由：适合现代 macOS 设置界面，代码量小，系统样式一致。AppKit 只补齐菜单栏和必要系统集成。

### 菜单栏优先

理由：切换动作高频且简单，菜单栏比完整主窗口更符合工具型应用。

### 不做后台轮询

理由：订阅地址切换是用户主动动作，后台轮询会增加耗电和复杂度。

### 切换前必须备份

理由：目标配置属于外部应用状态，写入失败或格式变化时需要可恢复。

### 敏感地址进入 Keychain

理由：订阅地址可能包含令牌，不能把完整明文随意写入普通日志或配置文件。

### 最低 macOS 版本

初始建议以现代 macOS 为基线。正式编码前需要根据目标用户设备决定最低版本。

### 沙盒策略

若目标配置位于沙盒外路径，Mac App Store 沙盒会增加授权复杂度。初期需要决定分发渠道，再决定是否启用沙盒。
