# 性能与耗电预算

## 总原则

这个应用的核心价值之一是“常驻但几乎没有存在感”。因此性能预算不是优化阶段才考虑的事情，而是架构约束。

## 预算目标

| 指标 | 目标 | 警戒线 |
| --- | --- | --- |
| 空闲 CPU | 接近 0% | 持续高于 0.5% 需要排查 |
| 空闲内存 | 小于 35 MB | 高于 60 MB 需要排查 |
| 冷启动到可交互 | 小于 800 ms | 高于 1500 ms 需要排查 |
| 菜单弹出响应 | 小于 100 ms | 高于 250 ms 需要排查 |
| 本地切换耗时 | 小于 300 ms | 高于 1000 ms 需要排查 |
| 手动网络检查 | 小于 3 s 超时 | 不允许无限等待 |

以上数值是初始目标，后续以真实设备和 Instruments 数据修正。

## 资源策略

- 不引入 Electron、WebView 壳或跨平台 UI 运行时。
- 不做后台轮询。
- 不保持网络长连接。
- 不使用自动测速。
- 不在空闲时扫描文件系统。
- 不加载大型资源图片。
- 不引入会常驻线程的大型三方 SDK。

## 启动策略

- 启动时只加载必要元数据。
- Keychain 明文读取延迟到用户查看或切换时。
- 历史事件只读取最近条目。
- 设置窗口懒加载。

## UI 策略

- 列表规模小，不做复杂虚拟化。
- 动画克制，优先系统默认动效。
- 不使用高频刷新视图。
- 不在文本输入时触发网络校验。

## 文件系统策略

- 写入前先比较目标值，值相同则不重复写入。
- 备份只在即将修改配置前创建。
- 备份数量有限，超过上限清理旧备份。
- 错误日志限制大小，写入内容脱敏。

## 验证方式

- 使用 Xcode 构建日志确认无不必要依赖。
- 使用 Instruments 的 Time Profiler 检查启动和切换路径。
- 使用 Instruments 的 Energy Log 检查空闲耗电。
- 使用 Allocations 检查窗口打开、关闭后的内存回落。
- 对 `SwitchService` 做单元测试，确认失败路径不会多次写入。
