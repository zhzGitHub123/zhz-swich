# 产品需求

## 背景

Codex 与 Claude 的使用环境可能需要在不同订阅地址之间切换。手工改配置容易出错，也难以确认当前到底启用了哪个地址。本应用的目标是把这件事压缩成低成本、低风险、可回滚的一步操作。

## 目标用户

- macOS 上同时使用 Codex、Claude 或多个订阅地址的个人用户。
- 希望快速切换，但不希望安装重型代理、后台服务或跨平台壳应用的用户。
- 对性能、耗电、内存占用和可控性敏感的用户。

## 核心目标

- 极简：只解决订阅地址管理与切换。
- 原生：使用 macOS 原生能力，不引入浏览器壳。
- 低资源：空闲时接近零 CPU，无后台网络轮询。
- 可恢复：每次写入本地配置前先备份，失败后可以回滚。
- 可解释：用户能看到当前启用目标、写入位置和失败原因。

## 初始功能

### 订阅档案

- 新增、编辑、删除订阅地址档案。
- 每个档案包含名称、目标应用、订阅地址、备注和更新时间。
- URL 输入时做基础格式校验。
- 对疑似包含令牌的地址进行敏感标记，展示时默认脱敏。

### 一键切换

- 用户选择一个档案并点击切换。
- 应用读取目标配置，创建备份，写入新地址，再验证写入结果。
- 成功后显示当前启用档案。
- 失败时显示明确错误，不更新“当前启用”状态。

### 回滚

- 最近一次成功切换保留可回滚备份。
- 回滚走同样的写入与验证流程。
- 回滚失败必须显示原始错误和备份位置。

### 手动检查

- 地址格式检查本地完成。
- 连通性检查只在用户点击时执行，不做后台自动探测。
- 网络检查设置短超时，避免拖慢界面或增加耗电。

## 非功能需求

- 空闲 CPU 目标为接近 0%。
- 空闲内存目标不超过 [性能与耗电预算](PERFORMANCE_BUDGET.md) 中的警戒线。
- 常驻状态不启动定时器、不轮询文件、不保持网络连接。
- 所有磁盘写入必须小而明确。
- 失败路径有可读错误，不允许静默吞掉。

## 非目标

- 不做代理服务。
- 不做订阅内容解析器。
- 不做多设备同步。
- 不做复杂规则引擎。
- 不做自动测速或自动择优。
- 不做账号登录。

## 成功标准

- 用户能在 3 次点击内完成一次切换。
- 用户能明确看到当前启用的是 Codex 还是 Claude 的哪个订阅地址。
- 用户能在切换失败后知道失败位置，并保留原配置。
- 应用空闲时对电量影响可忽略。
