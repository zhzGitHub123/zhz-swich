# 界面与交互规范

## 设计目标

- 现代、克制、清晰。
- 首屏直接可用，不做营销式欢迎页。
- 信息密度适中，避免把简单工具做成复杂控制台。
- 所有危险动作都能看清目标和后果。

## 信息架构

### 菜单栏弹窗

菜单栏是主入口，适合高频切换。

- 顶部显示当前启用目标。
- 中部显示常用档案列表。
- 每个档案提供一键切换按钮。
- 底部提供“打开设置”“检查当前配置”“最近结果”。

### 设置窗口

设置窗口用于低频管理。

- 左侧为目标应用：Codex、Claude。
- 右侧为该目标下的订阅档案。
- 详情区编辑名称、地址、备注。
- 高级区显示配置路径、备份位置和权限状态。

### 结果反馈

- 成功：显示目标应用、档案名称和完成时间。
- 失败：显示失败阶段、具体路径和可执行处理建议。
- 回滚：显示回滚来源和验证结果。

## 视觉原则

- 使用系统字体和 SF Symbols。
- 使用系统颜色，自动适配浅色与深色模式。
- 按钮层级明确：主操作、次操作、危险操作分开。
- 不使用大面积渐变、装饰图形或厚重卡片。
- 卡片和分组只用于真实分组，不做嵌套卡片。

## 交互原则

- 切换前明确展示目标应用和档案名称。
- 地址输入只做即时格式检查，不自动发起网络请求。
- 删除档案需要确认。
- 回滚需要确认，并展示将恢复的目标。
- 高级路径修改需要二次确认。

## 空状态

- 无档案时直接提供“新增订阅地址”。
- 目标配置未发现时说明原因，并提供“重新检测”和“手动选择配置文件”。
- 无备份时不展示回滚入口。

## 可访问性

- 所有图标按钮必须有可读标签。
- 关键状态不能只靠颜色区分。
- 支持键盘导航。
- 输入框错误要有文本说明。
- 支持系统动态字体范围内的基本缩放。
